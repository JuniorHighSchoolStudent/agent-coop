## 实施要求

1. 必须留存的关键交流：范围/权限/判据变更、澄清、异议、失败修复、替换/暂停/续作、接受/拒绝理由。在依赖动作前写回本请求；临时通知引用它。保留原作者、来源、时间/未知项、精确输入和适用范围；摘要不冒充原话或授权，无回复不等于同意。不采集全部私有聊天。
2. 稳定 finding_id 关联提出、回复、修复提交、验证、原审阅者或独立替补复核、关闭/撤回/承接；不把修复自报、resolved 按钮或退出码当独立关闭。监督沿 §7.5，冲突回原 owner；改输入后旧票失效但未决义务不丢。复用请求结果/原件与 handshakes，不新建 issues 状态库。
3. 正式证据/关键摘要、诊断日志、可重建投影/缓存、私有原始流分层；正式依据不得只留临时目录。归档结果落既有请求结果或归档回执事件，含精确清单、摘要算法/值、来源身份版本、位置、权限等级、policy id/revision、完整性/可读性验证、未决项承接、backup 状态及校验时间。Git 本地提交不等于异机备份；仅 local_only 须可见，不假成功。
4. 有具体可讨论的本地保留基线：公开正式证据在仓库支持/有效引用期内保留，项目退役另按 owner 策略审查，不自动删 Git 历史；脱敏诊断默认终态后 30 天到期评估（本地选择），如有调查/复核 hold 要有理由、owner、复核日期；raw 私有流最小化、未批准不能变长期档案。策略绑定每 attempt，未配置期限/权限/归档位置则阻断自动清理，不用无限保留冒充安全。
5. 归档和删除分离：终态确认、无活跃 writer/读取引用、无未闭合/hold、归档已验证且满足策略备份条件后才有界清理；先 dry-run 具体清单再沿既有授权执行，校验路径/摘要/版本防并发变化；失败、部分成功及重试记录可追溯，不因空间压力删证据。副本/备份同策略，hold 需明确延长而非永久积压。敏感内容误入不可变证据时限制访问、通知 owner、发布可公开的更正引用，任何历史改写另走明确授权，不能用不可变为泄露辩护。
6. 人工自举说明：当前只能把必要交付/关键交流写回 Git 请求记录并手工验证；原始 CLI 流可能暂在宿主临时目录，不宣称已归档备份。既有历史不伪造缺失交流；缺原件显示 unknown/缺证据及责任人。方案接受不授权本轮实际删除日志、上传远端或启用定时任务。

## 共同验收矩阵

| 项 | 判据 |
|---|---|
| A1 | 社区来源→取舍→owner 落点可追溯，期限不伪称社区标准 |
| A2 | 关键交流有落盘触发、身份/输入/来源和缺件阻断，摘要不冒充原件/授权 |
| A3 | finding 链可追，关闭权限独立，旧票失效不丢未决义务 |
| A4 | 正式原件、日志、投影、私有流分层；状态/协议不另起权威 |
| A5 | 归档清单/完整性/访问/恢复/备份状态可核验，本地 Git 不冒充异机备份 |
| A6 | 保留策略有期限、起算、hold 与复核，未配置/变更不可静默破坏在途绑定 |
| A7 | 清理需明确授权及并发/路径/摘要校验，部分失败/敏感证据有处置出口 |
| A8 | 人工现状与产品目标分开，验收 55–62 覆盖反例，旧 1–54 不变，无新增代码/依赖 |
