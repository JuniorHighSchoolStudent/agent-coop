# 文档组织规范补齐

用户要求参考社区实践补齐本仓文档组织规范；沿已授权多 agent 工作流推进。基线 main `a9bb47403c72e8f9afdce23aa27b68d3c06d2bec`。本请求只涉及文档治理，不改变产品切片；P0 仍待启动。

## 方案与实施计划

采用现有 AGENTS 作为规则唯一 owner、README 作为导航、roadmap 作为当前状态入口。比较过：全面按四象限搬迁会打断既有合同/历史引用；另设规范与索引会增加当前规模下的双写成本。此次选择原位补齐，后续按实际读者任务和责任边界拆分。

- Codex：调研、计划、派发、验证与集成，属作者，不能独立计票。
- CodeBuddy / deepseek-v4-pro：只修订 AGENTS.md 的文档组织规则及 README.md 的读者导航。
- CodeBuddy / glm-5.3 与 CodeBuddy / kimi-k3-2：分别用新只读会话复核同一候选及 C1–C8。
- Kimi Code CLI：独立监督角色/证据/状态/范围，必要监督不得省略。
- 调用约束沿 roadmap：CodeBuddy 并发 2、每轮 max-turns 20、最多两轮；Kimi 并发 1、单次十分钟，未知模型与未实施的硬预算保持可见。

步骤：①核对社区原文和既有入口；②实现规则与导航；③冻结候选并做链接、锚点与导航检查；④双席独立评审；⑤独立监督；⑥有证据才接收、更新当前状态、集成。文件路径与任务记录均复用本请求目录，不新增模板/注册表/生成器。

## 共同验收矩阵

| 项 | 判据 |
|---|---|
| C1 | 社区原文→采纳/不采纳理由→本仓落点可追溯；明确本地选择不是社区强制 |
| C2 | AGENTS 唯一开发规则 owner；README 仅导航；产品合同、当前状态和历史证据各有归属 |
| C3 | 按教程、操作指南、参考、解释区分目的；本仓无运行产品，不伪造教程或空目录 |
| C4 | 既有目录分工明确，命名/元信息/拆分原则可操作，现存文件映射完整 |
| C5 | 决策背景/取舍/后果/状态留存于既有请求闭环；被替代有指针，原始回执不重写，无新状态台账 |
| C6 | 变更、移动、删除同步检查消费者、链接/锚点、图/示例与权威合同；历史精确证据引用保真 |
| C7 | 新读者能定位规则、合同、当前工作、适配约定、配置例子、图和历史；无需全仓逐文件阅读 |
| C8 | 人工验证与未来自动门禁分开；本次不增加代码/依赖、不提前启动 P0 或产品能力 |

## 验证边界

复用临时 verify-docs.ps1 检查相对 Markdown 文件链接、design 验收编号与 git diff --check；另人工复核新增锚点/导航路径与 SSOT 映射。无产品测试入口，不声称通过产品测试或已配置 CI。目录规则只约束后续新增/修改；历史回执与既有稳定身份不为格式统一而重写。
